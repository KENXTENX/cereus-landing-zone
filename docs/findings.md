# Findings log

Every issue found while building and attacking this landing zone, and what was done about it.

| ID | Finding | Risk | Status | Resolution |
|---|---|---|---|---|
| F1 | Subscription inherits **User Access Administrator** from the parent tenant root (university tenant) | Tenant admins outside my control can grant themselves access to this subscription | Accepted | Lab data only. Production workloads go to a dedicated tenant I control |
| F2 | State storage allowed **shared account keys** | A leaked key gives full read/write to Terraform state with no per-user audit trail | ✅ Fixed | Entra ID auth for Terraform (`use_azuread_auth`) and users; `shared_access_key_enabled = false`. Verified: key access rejected, identity access works |
| F3 | Key Vault **purge protection** off (Checkov CKV_AZURE_110, CKV_AZURE_42) | A deleted vault or secret can be destroyed immediately, including by an attacker | ✅ Fixed | Purge protection on. Irreversible by design |
| F4 | State storage was **locally redundant** (CKV_AZURE_206) | A regional outage loses Terraform's record of all infrastructure | ✅ Fixed | GRS replication. Plan verified as update-in-place before apply |
| F5 | **Access to the state file** wasn't logged (CKV2_AZURE_21) | Can't tell who read or changed the state | ✅ Fixed | Blob read/write/delete logs sent to the central workspace (`landing-zone/state-logging.tf`) |
| F6 | **Private endpoints** absent for Key Vault and state storage (CKV2_AZURE_32, CKV2_AZURE_33) | Services are reachable from the internet at the network layer | Accepted | GitHub-hosted runners can't reach private endpoints. Mitigated by Entra-only auth, IP allowlist on Key Vault, TLS 1.2. Revisit with self-hosted runners |
| F7 | Microsoft-managed encryption keys, not customer-managed (CKV2_AZURE_1) | Less control over key lifecycle | Accepted | No compliance driver; CMK adds rotation burden for a lab |
| F8 | Queue logging not configured (CKV_AZURE_33) | — | Not applicable | Queue service isn't used |
| F9 | **Local Checkov run silently skipped the graph-based (CKV2) checks** that ran in CI | A clean local scan can be falsely reassuring | ✅ Fixed | CI pins Python and Checkov versions and is the authoritative gate |
| F10 | Public-storage policy **also denies requests that omit the setting** | Positive: blocks insecure-by-omission | Noted | Tests needed explicit flags to prove each control independently |
| F11 | GitHub OIDC subject uses **immutable owner/repo IDs** | Name-based trust could be hijacked if a repo name were reused | ✅ Fixed | Federated credentials match `repo:OWNER@ID/REPO@ID:...` |
| F12 | Key Vault admin role was assigned to **whoever runs Terraform** | First CI run would have replaced the human admin with the pipeline identity | ✅ Fixed | Admin pinned to an explicit object ID variable |
| F13 | Pipeline IDs printed in **workflow logs** | Subscription/tenant/object IDs visible once the repo is public (reconnaissance) | ✅ Fixed | Moved to GitHub secrets so they're masked; old run logs deleted before going public |
| F14 | **Bootstrap state** lives only on my laptop | Losing the machine loses Terraform's record of the state storage and identities | Open | Planned: move to remote state or a backed-up location |
| F15 | Merge to `main` wasn't **blocked** by a failing scan on a free private repo | A failing PR could still be merged (deploy would still be blocked by the gate) | ✅ Fixed | Repo made public; branch protection requires the scan and plan checks |
| F16 | The allowed-locations policy **blocked incident response** on a resource that predates it: patching a critical Next.js CVE and closing public ingress on the Central US demo were both denied | A Deny guardrail can stop the fix as well as the mistake, leaving a vulnerable app exposed | ✅ Fixed | Revision deactivated (an action, which policy doesn't evaluate), then a Terraform exemption scoped to one resource group and one assignment, expiring 2026-12-01. Made unnecessary once Central US was approved (F17); left to expire on 2026-12-01 because the resource lock blocks deleting it (F24) |
| F17 | **Neither approved region could host the workload's database.** East US is `OfferRestricted` for PostgreSQL Flexible Server on this subscription; East US 2 returned `SkuNotAvailable` for B1ms on two attempts weeks apart (the capability list advertised it both times) | An allowed-regions list that doesn't match what the subscription can deploy pushes real workloads onto exemptions | ✅ Fixed | Central US added to the allowed locations, with this evidence. Verified with `az postgres flexible-server list-skus` and a throwaway create in East US 2 (deleted) |
| F18 | The hand-built demo database has **no geo-redundant backup**, and Checkov flags it for not using a private endpoint (CKV_AZURE_136, CKV2_AZURE_57) | A regional outage loses the demo data | Accepted / not applicable | Fixture data only, and geo-backup can only be chosen at server creation. The server already has private access through a delegated subnet with no public endpoint |
| F19 | The demo **Key Vault accepts connections from the internet** (default action Allow, public network access on) (CKV_AZURE_109, CKV_AZURE_189, CKV2_AZURE_32) | Anyone can reach the vault's endpoint; access still needs Entra ID and an RBAC role | Open | Deny by default with a subnet rule for the Container Apps subnet and the admin IP, verified by restarting the app |
| F20 | The demo Key Vault has **purge protection off** (CKV_AZURE_110, CKV_AZURE_42) | A deleted vault or secret can be destroyed immediately | Open | Enable in its own PR. It's a one-way change, as in F3 |
| F21 | The demo subnets have **no network security groups** (CKV2_AZURE_31) | No subnet-level filtering if something else lands in the VNet | Open | Add NSGs that allow what Container Apps and PostgreSQL need, in their own PR |
| F22 | **A failed `terraform plan` showed as a green check.** The plan step piped into `tee`, and the default Actions shell (`bash -e`) doesn't set `pipefail`, so the step took `tee`'s exit code | A broken or erroring plan could be approved and merged as if it were clean | ✅ Fixed | Plan jobs set `shell: bash`, which adds `pipefail`. Proven on PR #4: the same 403 errors went from a green check to a red one |
| F23 | Reader can't plan Container Apps or Jobs: the provider calls `listSecrets`, which Reader doesn't include | Either the apps stay outside Terraform, or the plan identity needs more than read | Accepted | Custom role with only the two `listSecrets` actions, assigned to the plan identity on `rg-cereus-demo` only (bootstrap). All secrets there are Key Vault references |
| F24 | **The demo's `CanNotDelete` lock blocked deleting the F16 exemption**, so the landing zone apply for F17 failed on `main` (`ScopeLocked`) and the region change never applied. The failure went unnoticed until the next apply | Governance changes can silently not happen; the lock covers extension resources (exemptions, role assignments) at that scope, not just the resources in it | ✅ Fixed | `removed` block with `destroy = false`: Terraform stops tracking the exemption and leaves it to expire. The lock stays. Check the Apply job after every merge, not just the PR checks |
| F18 | **Redeploying to a fresh tenant exposed a hidden dependency.** `bootstrap/` assigns RBAC Administrator on `rg-cereus-core`, but that resource group is created by `landing-zone/`; in the original tenant it only worked because the RG already existed. Also surfaced: two subscriptions both named "Azure subscription 1" across tenants; the az CLI serving a cached account list after a rename; and three clones of this repo on one machine, one of which produced a "17 to add" bootstrap plan because it held no state | The bootstrap isn't standalone, so rebuilding from code in a new tenant fails at step one; near-identical subscription names and duplicate clones both invite applying to the wrong target | Open | Unblocked by pre-creating `rg-cereus-core` with Terraform's tags and importing it into the landing-zone state before apply (`rg-cereus-demo` also pre-created, empty, as the demo custom role's assignable scope). Proper fix: move `gh_apply_rbac_core` into `landing-zone/` beside the RG it scopes to. Subscription renamed `cereus-labs`; `az account clear && az login` after renames; `az account show` and `git branch --show-current` before every Terraform session; one clone per machine in `~/Projects`. Full redeploy (bootstrap + landing zone, 21 resources) completed in one evening with no code changes |
